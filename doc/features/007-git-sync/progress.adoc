=== SL-5…SL-8 — этап E2: статусы, commit, push, секреты (2026-08-17)

E2 нарезан и пройден одной сессией после решения владельцем всех семи развилок (см. «Решённые вопросы» аналитики).

*SL-5 — статус репозитория.* `RepoStatus`/`StatusEntry`/`FileStatus` в контракте, `JGitSync.status()` (git status + `BranchTrackingStatus`, счётчики диффа одним `DiffFormatter`-проходом), карточка со счётчиками `↓N ↑N` и «N изменений», чипы-фильтры, метки `M`/`A`/`D`/`?` в списке, панель `COMMIT · N`.
Ревью (три линзы) — два блокера закрыты: отказ чтения статуса больше не выдаёт себя за «чистый репозиторий» (исключение доезжает до состояния `Failed` экрана), дубли путей из пересекающихся наборов JGit сведены («один путь — одна строка», `changeCount` считает файлы).
Прочее принятое: статус `D` дозаявлен в `FR-10` (удаления не исчезают бесследно), `diffCounters` ограничен `PathFilterGroup` путей статуса (без чтения untracked/ignored), «первый репозиторий» унифицирован одной функцией на все методы, device-кейс `TC-9` переведён на штатный shallow-клон, `TC-38` дозаявлен (счётчики и подписи), пустой фильтр получил подпись «Изменений нет», KDoc E1 обновлён.
Отклонено с обоснованием: `↓0` после клона — честный ноль на момент клона (OQ-5 принял счёт от последнего сетевого обращения; подпись времени придёт с pull в E3); `clickable(enabled=false)` публикует disabled-семантику сам — дублировать не нужно; кэш `visibleFiles` сверх индекса строк — преждевременная оптимизация при допущении «десятки мегабайт, не монорепо»; типографика карточки (`metadata` вместо смеси body 13/mono 12 прототипа) — отступление, названное здесь: ролей 13px в типографике нет, новая роль — решение дизайна.
Названная цена `НЕДАВНИЕ`: на свежем клоне mtime почти одинаков и порядок вырождается — семантика фильтра остаётся выбором реализации до ревизии дизайна.
Остаток `FR-10` «для папки — число вложенных»: плоский список папочных строк не имеет — вынесено вопросом владельцу в отчёте E2, клаузула не закрыта.

*SL-6 — commit.* `author()`/`commit(paths, message, author)` в контракте (`CommitAuthor`, `GitCommitError`), JGit: `add` + `setOnly` на каждый путь (в коммит не утекает ничего сверх отмеченного), авторство пишется в конфиг репозитория и переживает перезапуск (`FR-22`).
Экран «03»: индекс с чекбоксами и счётчиками диффа, `ИНДЕКС · N ИЗ M`, поле сообщения, счётчик `50 / 72 симв.` по первой строке (`FR-19`), «подпись: gpg off» — честная константа.
Диалог авторства чертёжным блоком — дополнение макета (решение OQ-8), отступление названо.

*SL-7 — push.* `push()` в контракте (`PushResult`/`GitPushError`), JGit: только `refs/heads/<текущая>`, классификация non-fast-forward/сеть/авторизация; переключатель «Отправить в origin после коммита» включён по умолчанию, кнопка `COMMIT & PUSH`.
Отказ push не откатывает коммит и едет отдельным сообщением в `Done.pushFailure` (`FR-21`); каждый текст отказа кончается «коммит сохранён локально».
Решение OQ-6 соблюдено: очереди нет, ошибка сразу.

*SL-8 — секреты и токен.* `Secret` с задушенным `toString` (секрет не печатается ни из модели, ни из `GitAuth`), `AndroidSecretStore` — файл + AES-256-GCM-ключ в Android Keystore (решение OQ-2, без Tink), токен предъявляется `UsernamePasswordCredentialsProvider(token, "")` и запоминается только после успешного клона; push переиспользует сохранённый токен (`FR-26`).
Форма: сегмент `ТОКЕН` активен, поле маскировано (`PasswordVisualTransformation`), успех очищает поле; `FR-30` реализован — URL со встроенными кредами отвергается с подсказкой, секрет в сообщении не повторяется.
Тесты: 15 новых host-кейсов по слайсам, device: `TC-15` (×2), `TC-20`, `TC-30` (×2, включая побайтовый поиск секрета по каталогу данных — не найден), `TC-7`/`TC-9` статусов; все прогоны с `leaveApksInstalledAfterRun=true`, пакет приложения жив.
Живой push против настоящего сервера — ручной `TC-27`: потребности названы в отчёте координатору, токены агент не добывал и не вводил.

*Раунд ревью E2* (сводный отчёт четырёх взглядов) — два блокера и существенные закрыты в тех же слайсах:

* *Блокер 1 + находка A (`FR-21`)*: отказ push теперь доезжает до пользователя — `onCommitted(pushFailure)` в контракте экрана коммита, плашка и кнопка `PUSH · ↑N` на карточке репозитория (путь повтора, которого не существовало); кнопка — дополнение макета «01», отступление названо; `TC-41` дозаявлен.
* *Блокер 2*: device-половины `TC-18`/`TC-19` написаны офлайн — push в `file://`-bare с проверкой вершины remote, «нет сети» удалением remote, non-fast-forward конкурирующим push из seed-фикстуры.
* Гонка двойного тапа (`TC-40` дозаявлен): фаза `Committing` занимается синхронно до IO-хопа, пути и сообщение снимаются на момент запроса; `start()` экрана коммита защищён фазой и ловит отказ чтения текстом.
* Рубежи шва падают независимо: пустой список путей — `Failed` в `JGitSync.commit`; гейт кредов в URL продублирован в `JGitSync.clone` (`GitSyncError.CredentialsInUrl`, общий `hasCredentialsInUrl` — ловит и бессхемную пару, но пропускает scp-форму `git@host:` без секрета).
* Секреты: токен хранится в паре с хостом и предъявляется только своему `https`-origin (чужой сервер и голый `http` не получают ничего); форма отвергает токен-режим для не-`https`; `clearToken` удаляет и Keystore-ключ; запись атомарна (`tmp` + `renameTo`); `key()` синхронизирован; чистка URL жадная — пароль с `@` внутри не оставляет хвоста.
* Удаления: `commit` стейджит отмеченный `D`-файл через `rm` (обычный `add` удалений не видит) — device-кейс; «чужой pre-staged файл не утёк» и битый тег GCM закрыты кейсами; фейк запоминает авторство до исхода — как JGit.
* Названные отклонения: plaintext-`String` в памяти не затирается; ключ без `setUserAuthenticationRequired`/`setUnlockedDeviceRequired` (KDoc хранилища); цвета снятого чекбокса и выключенного toggle взяты из ролей палитры, а не из точных значений макета — той же строкой, что у `SquareToggle` в SL-3.
* Отклонено с обоснованием: `push()` без репозитория отдаёт `PushFailed` с неточным текстом — недостижимо из потока commit→push, помечено в KDoc; detached HEAD — пометка в KDoc, гейт придёт с E3; повторное чтение `entries` при пересоздании композиции решено фазовым гейтом `start()`, а не `rememberSaveable` отметок (дешевле и достаточно до хостинга).

Коммиты E2 идут не по одному на слайс, а кодом и доками: слайсы одной сессии росли вокруг общих контрактных файлов (`GitSync.kt`, `JGitSync.kt`, фейк), и коммит на слайс дал бы некомпилируемые точки истории — отступление от цикла закрытия названо здесь.

Ревью: security-находка *симлинк-выход за рабочую копию* принята и закрыта в слайсе — `resolve()` получил канонический рубеж (`canonicalFile` обязан остаться под корнем копии; содержимое клона контролирует автор remote, JGit честно создаёт симлинки), `.git` закрыт в любом сегменте, `listFiles` не заходит в симлинк-каталоги и не отдаёт симлинк-файлы; закрыто device-тестом с настоящими `Os.symlink`.

Повторное security-ревью (узкий взгляд по указанию координатора) нашло остатки того же класса, все закрыты в слайсе:

* *Ссылка внутрь копии на `.git`* (`notes.adoc → .git/config`) обходила канонический рубеж — добавлен NOFOLLOW-проход по сегментам (`Files.readAttributes(NOFOLLOW_LINKS)`): по ссылке не ходим вовсе, ни при проверке, ни при чтении; заодно обесценено TOCTOU-окно.
* `listDocuments` не фильтровал симлинки и предлагал документы-призраки — фильтр тот же, что в `listFiles`; перечни одной копии больше не расходятся.
* *Уборка каталогов шла за симлинками*: `File.deleteRecursively` следует за ссылками-каталогами — `cleanUp` неудачного клона и уборка тестовых фикстур переведены на path-API `deleteRecursively`, которая удаляет саму ссылку.
* `.git` сравнивается без учёта регистра (страховка регистронезависимого тома); `workTree.canonicalFile` — под `try`.
* Заведён host-прогон рубежей (`androidHostTest`, JVM, без устройства): именные правила + симлинк-кейс, чтобы CI без телефона не был слеп к security-рубежу; device-тест дополнен кейсами «ссылка на `.git`» и «перечень без призраков».
* Принято без починки, осознанно: hard links вне модели угроз (checkout их не материализует, «другого пути» у них нет); TOCTOU — условие пересмотра записано в ограничениях аналитики (включается с появлением pull параллельно записи редактора).

[IMPORTANT]
.Инцидент прогона device-тестов, признание
====
Прогон `TC_36`-симлинк-теста до починки уборки *успел причинить вред*: `@AfterTest` с `File.deleteRecursively` прошёл по ссылке `outside → filesDir` и рекурсивно удалял данные приложения — почти наверняка это и снесло persisted-право на папку, которое координатор потерял на ручных кейсах (версия «AGP снёс APK» — вторая половина той же потери).
Уборка всех device-фикстур Git переведена на несследующий за ссылками path-API; правило координатора «после connected-прогона вернуть основной APK на устройство» принято к исполнению.
====
Прочие принятые находки: `heldSource` — решение «мост не персистит, восстановление после перезапуска — обязательство хостинга» записано в KDoc (относительный путь однозначен только в паре с репозиторием), поле `@Volatile`; отказы перечисления различены (`NotFound`/`ListFailed`); запись только в существующие файлы названа контрактом и закрыта тестом; `RepositoryScreenState.Failed` вместо вечного `Loading`; device-покрытие `listFiles`; матрица и реестр приведены.

Отклонено или отложено с обоснованием:

* `start()` во время загрузки глотает повторный запрос — принято как известное ограничение: единственный источник повторного вызова в E1 — возврат с экрана клонирования, который случается после терминального события, а не параллельно; перезапрос-после-текущего добавится с pull (E3), где параллельность станет реальной.
* Обновление только по `LaunchedEffect(model)` и пользовательская половина `TC-6` — обязательство этапа UI (врезка экранов), записано в остатках E1.
* «Два понятия файлов» (список экрана рекурсивный, `listDocuments` моста — `.adoc` корня): хостингу редактора запрещено использовать `listDocuments` как выборщик файлов репозитория — источник выбора это экран репозитория; бинарные файлы через мост дают «не UTF-8» отказ, что для E1 приемлемо, лимиты размера — вместе с ADR-004 на этапе UI.
* «Для папки — число вложенных файлов» из `FR-10` в плоском списке неприменимо — остаётся на E2 вместе с фильтрами.

Ревью (линзы спеки и безопасности, security-review) — принятые находки закрыты в этом же слайсе:

* `remoteUrl` снимка чистится `sanitizedGitUrl` — токен из URL не утекает в карточку ветки (`NFR-8`).
* Имя папки валидируется на платформенной границе (`isSafeDirectoryName`): `../…` не выводит цель за корень хранилища; новый класс отказа `InvalidDirectory` (`FR-7`).
* Занятость цели распознаёт и одноимённый файл, и нечитаемый каталог; чистка разрешена только каталогу, созданному самой операцией.
* Терминальное событие ровно одно: `Finished` уходит после закрытия JGit; чистка выполняется и при `Error` (OOM — заявленный риск), `.git` удаляется первым, чтобы огрызок не сошёл за репозиторий.
* Отмена прерывает поток JGit (`runInterruptible`), новый device-кейс `TC-5` с отменой посреди клона.
* `errorOf` расширен: `NotSupportedException` → `InvalidUrl`; `SocketException`/`NoRouteToHost`/`SSLException` → `Network`; классы отказов сверяются device-тестами.
* `INTERNET` переехал в main-манифест — Git-слой стал продуктовым кодом.
* Спайк E0 (`JGitSpikeTest`) снят с автоматического прогона `@Ignore`: сетевым обращениям в автоматических тестах хода нет (границы работ); файл оставлен образцом до настоящих тестов E1.

Отклонено с обоснованием: привязка `reposRoot` к `Context.filesDir` — врезка в приложение, согласуется на этапе UI (координатор); явная декларация `kotlinx-coroutines-core` — вынесена вопросом в отчёт (правило «новая зависимость — спросить»).

Известное ограничение (записано ревью): отказ авторизации распознаётся по тексту исключения JGit — типизированной причины у него нет; ручные кейсы E2 уточнят.

Постфактум-признание: коммит SL-2 ушёл с красным host-тестом `TC_4_messagesStripCredentialsEmbeddedInUrl` — прогон перед коммитом отчитался `UP-TO-DATE` со старого состояния, а новый класс `InvalidDirectory` ломал ассерт «в каждом сообщении есть URL».
Обнаружено и починено первым же свежим прогоном в SL-4 (ассерт разнесён: URL обязателен там, где сообщение об адресе).

Сделано: `git/GitSync.kt` (интерфейс, `CloneRequest`/`CloneEvent`/`CloneProgress`/`RepositorySnapshot`, `GitSyncError` с готовыми текстами, `sanitizedGitUrl`), `git/CloneProgressTracker.kt` (арифметика прогресса в общем коде), `FakeGitSync` с валидацией сценариев и `GitSyncContractTest` (10 тестов).
Шов — интерфейс с платформенной фабрикой, по прецеденту `DocumentFileAccess`; типы JGit в `commonMain` не появились.

Ревью двумя линзами приняло решения, ушедшие в документы:

* `FR-2` из «Закрывает» SL-1 перенесён в SL-3 — до экрана артефакта «разделы UI не показываются» не существует; реестр плана поправлен.
* `TC-3` уточнён в аналитике: возрастание прогресса — *внутри фазы*, глобальной монотонности у клона нет (так ведёт себя и нативный `git`).
* `FR-7` дозаявлен: занятая целевая папка — штатный отказ, чужие файлы не зачищаются; сообщения не содержат учётных данных из URL (`sanitizedGitUrl`, `NFR-8`).
* Тавтологичные тесты порядка событий переоформлены в дымовой тест инфраструктуры подделки (без `TC-*`, с обоснованием в KDoc); подделка валидирует сценарии контрактом «Progress…, затем ровно один терминал».
* Отклонено с обоснованием: `openRepository()` в интерфейсе раньше SL-2 — SL-2 идёт следом в той же сессии, дробить интерфейс на два коммита дороже, чем принять недельный люфт реестра.

Вопрос дизайну (в отчёт владельцу): макет «05» показывает «скорость» без единицы; модель отдаёт объекты/с — байтов JGit не сообщает.

=== SL-0 — спайк E0: JGit 7.x на устройстве (2026-08-17)

Спайк разрешён до одобрения спеки; полный цикл закрытия слайса к нему не применялся — результат спайка не код, а факты.
Гипотезы H1, H2, H5 подтверждены, H3 снята; числа, точные ошибки и вердикты — в xref:research.adoc#spike-e0[research.adoc, раздел «Спайк E0»].

Отступления от плана и находки:

* Прототип живёт не в `shared/src/androidDeviceTest`, как предполагал план, а в `androidApp/src/androidTest/kotlin/io/github/olegnyr/adocmobile/git/JGitSpikeTest.kt`: конвейер дексации device-тестов KMP-модуля падает на Java records из JGit 7.x («Record desugaring … without a global-synthetics consumer»), конвейер приложения дексует их штатно.
Это меняет размещение Git-device-тестов E1 — зафиксировано риском в плане.
* Прототип помечен выбрасываемым, но *пока не удалён*: он же — рабочий образец для device-тестов E1 (запуск, замеры, targetContext, оркестровка `am force-stop`).
Удалить при активации E1, когда появятся настоящие тесты.
* Сопутствующие правки сборки: JGit в каталоге версий (`jgit = 7.7.1.202607240634-r`, только для `androidTestImplementation`), `testInstrumentationRunner` у `:androidApp`, разрешение `INTERNET` в debug-манифесте (нужно тесту H1; в main-манифест приедет с реальным Git-слоем).
* Каталоги спайка на устройстве удалены (`run-as … rm -rf files/spike-*`); временная проверка дексации main-APK (`debugImplementation(libs.jgit)`) откатена сразу после факта.
