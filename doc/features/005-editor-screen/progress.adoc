=== SL-2 — живое превью · 2026-08-17

`PreviewPipeline` по образцу `AutosaveRunner`: экземпляр на документ в его дочернем scope, отмена доезжает до прерывания движка; сигнал видимости «вкладка ∧ документ ∧ передний план», фон глушит движок.

Устройство-проверки (координатором, по сценарию слайса)::

Плашка остаётся закрытой юнит-тестами; спровоцировать её вживую получится при отказе реальной записи (нет места), и это честно записано.

=== SL-7 — «Поделиться» · 2026-08-17 · TC-20 пройден на устройстве, шлюз MVP закрыт

Сделано::
Пункт «Поделиться» в меню документа: `shareRequested` переиспользует запись «ухода в фон», ждёт совпадения диска с полем и лишь затем зовёт платформенный шов; отказ записи отменяет отправку — устаревший файл не уходит.
Исполнение — `ACTION_SEND` c SAF-URI в `EXTRA_STREAM` (+`ClipData` для гарантии переноса права), `Intent.createChooser`; собственного `FileProvider` нет.
Четыре `TC_20_*` теста по TDD, `check` зелёный.

Проверено на устройстве::
Правка с горящей меткой → «Поделиться» → системный диалог; Gmail принял SAF-URI и создал вложение ровно с текстом поля, включая символ, набранный за миг до вызова, — немедленная запись сработала.
Ограничение «не все получатели принимают SAF-URI» на этом пути не проявилось; всплывёт — решение о `FileProvider` за владельцем.

Решение вне спеки::
При живом отказе записи (плашка горит, новых правок нет) «Поделиться» молчит: отправка того, что на диске, противоречила бы `FR-20`.

Наблюдение на приёмку::
Из открытого документа к списку документов папки нет пути короче повторного системного диалога («Открыть папку…») — само право живо, диалог избыточен.
Кандидат в пункт меню «К списку» — решение владельца, записано открытым вопросом.

=== SL-9 — вкладки только при открытом документе · 2026-08-18 · TC-22 пройден

Полоса `РЕДАКТОР` / `ПРЕВЬЮ` показывается только в состоянии открытого документа: на пустых состояниях и в списке папки её нет — раньше она висела над кнопкой «Открыть папку» и ничего не переключала.
Сверх буквы `FR-22`: закрытие документа сбрасывает выбор на `РЕДАКТОР`, иначе следующий документ открывался бы на превью предыдущего.
Проверено на устройстве вместе с `TC-21`.

Зависимость `compose-ui-backhandler` подтверждена (внесена реализацией без вопроса — по границам плана вопрос требовался, агенту указано).
Сброс вкладки на `РЕДАКТОР` при закрытии документа подтверждён и дозаявлен в `FR-22`.
Пустой app bar в состояниях без документа оставлен как есть — вопрос дизайну не заводится.


=== Дефект раскладки при клавиатуре — окно панорамировалось вместо изменения размера · 2026-08-18

Симптом (снимок владельца)::
После работы с превью и возврата в редактор шапка с именем файла и полоса вкладок уехали за верхний край экрана, а между панелью быстрой вставки и клавиатурой встал пустой промежуток примерно в её высоту.
Текст при этом цел, состояние документа не пострадало — ломалась только раскладка.

Причина, установленная на устройстве::
`dumpsys window` показал у окна приложения режим `sim={adjust=pan}`.
`AndroidManifest.xml` не объявлял `windowSoftInputMode` вовсе, а нераспознанный режим система разрешает панорамированием: окно целиком сдвигается вверх, чтобы поле ввода не оказалось под клавиатурой.
Приложение при этом работает edge-to-edge и отступ клавиатуры несёт само — `imePadding` на контейнере панели (`FR-1`, `NFR-7` фичи 006).
Два механизма складываются: система сдвигает содержимое вверх, а `imePadding` дополнительно отодвигает панель — отсюда и ушедшая шапка, и промежуток.

Починка::
Активность объявляет `android:windowSoftInputMode="adjustResize"`: система перестаёт панорамировать окно и отдаёт отступ клавиатуры вставками, которых и ждёт `imePadding`.
Правка в одну строку манифеста, кода не касается.

Не воспроизведено по шагам::
Три прогона по описанию владельца (превью → редактор → касание текста; прокрутка к концу документа) дали правильную раскладку — дефект проявляется не на каждом открытии клавиатуры.
Поэтому починка сделана по установленной причине, а не по повторению симптома.
Владелец подтвердил на устройстве в тот же день: раскладка держится.
Инструментальным кейсом не закрыта: режим окна — свойство манифеста, проверяемое только живым прогоном с клавиатурой.
