[IMPORTANT]
.Почему производительность вынесена в E2, а не сделана сразу
====
Соблазн сделать `FR-26` в первом же слайсе велик — замеры `T-010` уже показали, что без него не обойтись.
Но окно и инкрементальность оптимизируют то, чего в `SL-1` ещё нет: пока сканер распознаёт два вида блоков, оптимизировать нечего, а тест `TC-37` будет зелёным по случайности.

При этом *архитектурное* требование учитывается с первого слайса: сканер отдаёт список диапазонов отдельно от их применения (`FR-25`).
Оптимизация в E2 тогда становится добавлением, а не переделкой.
Если это окажется не так — план перепланируется, см. риски ниже.
====

⚠️ Спросить::

Расхождение с эталоном, не перечисленное в разведке.
Любое изменение порядка инлайн-проходов.
Новая зависимость.

🚫 Никогда::
Тип из Compose в сигнатурах сканера.
Проход сканера внутри `transformOutput`.
Подсветка всего документа вместо видимого окна.
Собственный парсер AsciiDoc.
Утверждение о синтаксисе «по памяти», без источника или прогона.
Коммит при красном прогоне.

== Риски и точки перепланирования

* Инлайн-проходы могут оказаться дороже бюджета даже на видимом окне → выяснится на `SL-5`; тогда часть конструкций уезжает в `C`/`W` по MoSCoW, а не отменяется вся фича.
* Разделение «диапазоны отдельно, применение отдельно» может не выдержать инкрементальности → выяснится на `SL-5`; это единственное место, где возможна переделка `SL-1`, и потому оно названо явно.
* Корпус для `SL-6` пересекается с корпусом сверки превью из потока 3 → делать один общий, а не два.
