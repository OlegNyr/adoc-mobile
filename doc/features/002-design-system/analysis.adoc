== Видение

Проблема::
Каркас показывает интерфейс темой Material по умолчанию: светлый фон, скруглённые углы, системные шрифты.
Дизайн проекта — противоположный: тёмный технический чертёж, прямые углы, три конкретные гарнитуры.
Пока темы нет, каждый следующий экран придётся красить вручную, и расхождение с макетами будет накапливаться.

Для кого::
Непосредственный потребитель — разработчик: тема задаёт словарь, которым описываются все последующие экраны.
Конечный — пользователь, для которого тёмная тема заявлена свойством продукта (xref:../../user-stories.adoc#US-E8-01[US-E8-01]).

Желаемый результат::
Экран собирается из ролей, а не из шестнадцатеричных значений.
Разработчик пишет «фон панели», а не `#17191c`; «заголовок экрана», а не «Barlow Condensed 600, 19sp, трекинг 0.04em».
Отклонение от макета становится видимым в коде, а не растворяется в числах.

Не-цели::
+
--
* *Не значения светлой темы.* В макетах она не проработана, выдумывать значения нельзя — это записано в описании дизайна.
Но *структура* под две схемы закладывается сразу: роли определяются набором, а тёмная палитра — одной из его реализаций.
Светлая тема заявлена продуктом (xref:../../user-stories.adoc#US-E8-01[US-E8-01]), и добавление её значений позже должно быть заполнением набора, а не переделкой темы.
* *Не семантические цвета* `error`/`warning`: способ вывода задан, конкретные значения не утверждены.
* *Не экраны.* Здесь только словарь и один компонент; экраны — поток 5.
* *Не полный набор компонентов.* Кнопки, поля, переключатели делаются вместе с экранами, которым они нужны, а не впрок.
--

Ценность и почему сейчас::
Это последняя задача каркаса: после неё поток 0 закрыт и работа расходится на независимые ветки.
Дешевле всего сделать сейчас — пока нет ни одного экрана, который пришлось бы переписывать под тему.

== Критерии приёмки

[NOTE]
Тип `automatable` означает `commonTest` без устройства.
Значения проверяются сверкой с xref:../../design/design.adoc[описанием дизайна] — оно источник истины, тест ловит расхождение с ним.

=== TC-1 (happy, automatable) — палитра содержит все роли

`[@test]` (нет)

[source,gherkin]
----
Given тёмная палитра проекта
When  запрашивается любая из ролей раздела «Палитра» описания дизайна
Then  роль определена и её значение совпадает с записанным в описании дизайна
----

Проверяются все роли до единой, включая служебные: фон экрана, панели, приподнятая и утопленная поверхности, фон панели вставки, три границы, пять оттенков акцента, текст на акценте, четыре уровня текста, комментарий, номера строк.
Тест перечисляет их явно: пропущенная роль должна валить прогон, а не молча отсутствовать.

=== TC-2 (happy, automatable) — тёмная тема применяется по умолчанию

`[@test]` (нет)

[source,gherkin]
----
Given приложение запущено без сохранённой настройки темы
When  строится тема
Then  используется тёмная палитра, а не системная схема Material
----

=== TC-3 (happy, automatable) — все формы прямоугольные

`[@test]` (нет)

[source,gherkin]
----
Given тема проекта
When  запрашивается любая из форм темы (мелкая, средняя, крупная)
Then  форма прямоугольная, радиус скругления равен нулю
----

Скругления выключаются в теме, а не подавляются по месту у каждого компонента — это записано в описании дизайна.

=== TC-4 (happy, automatable) — три гарнитуры доступны

`[@test]` (нет)

[source,gherkin]
----
Given ресурсы шрифтов проекта
When  запрашивается семейство heading, body или mono
Then  семейство разрешается в загруженный ресурс, а не в системный fallback
----

=== TC-5 (edge, automatable) — стили типографики соответствуют описанию

`[@test]` (нет)

[source,gherkin]
----
Given типографика темы
When  запрашивается стиль «заголовок экрана», «подпись кнопки», «код редактора» или «служебная метка раздела»
Then  гарнитура, начертание, кегль и межбуквенный интервал совпадают с таблицей «Типографика» описания дизайна
----

=== TC-6 (happy, manual) — чертёжный блок у края экрана

[source,gherkin]
----
Given чертёжный блок размещён вплотную к горизонтальному краю экрана
When  экран отрисован на устройстве
Then  все четыре метки «+» видны целиком и не обрезаны
And   внутренние отступы содержимого блока не изменились по сравнению с блоком в середине экрана
----

Тип `manual`: метки выносятся за границу контейнера на 5–6 px, и обрезание проявляется только при реальной отрисовке.
Проверяется на подключённом устройстве снимком экрана.

=== TC-7 (edge, automatable) — набор ролей не привязан к тёмной схеме

`[@test]` (нет)

[source,gherkin]
----
Given определение набора ролей палитры
When  создаётся вторая схема, где каждой роли присвоено произвольное отличное значение
Then  тема собирается с этой схемой, компиляция и построение проходят
And   ни одно значение тёмной палитры не участвует в результате
----

Смысл проверки — не в самой второй схеме, а в том, что схема отделена от набора ролей.
Тест-заглушка со случайными значениями фиксирует эту границу до того, как появятся настоящие светлые значения; когда они появятся, заглушка заменяется на них.

=== TC-8 (negative, automatable) — значение в обход роли не проходит

`[@test]` (нет)

[source,gherkin]
----
Given исходники модуля темы и экранов
When  выполняется проверка на литералы цвета вида #RRGGBB вне файла определения палитры
Then  таких литералов не найдено
----

Это защита от эрозии: без неё роли заводятся один раз, а дальше цвета появляются по месту.
Если проверку не удаётся сделать дешёвым тестом, она переносится в CI как отдельный шаг — но не отменяется.

== Открытые вопросы

* [ ] Шрифты нужно положить в репозиторий бинарными файлами. Barlow, Barlow Condensed и JetBrains Mono распространяются по SIL Open Font License — лицензия допускает встраивание, но требует приложить текст лицензии. Подтвердить, что кладём файлы в репозиторий, а не тянем зависимостью.
* [ ] Когда выводить значения светлой темы. Выводить их не с нуля: дизайн-система «Industry» изначально светлая, в её `styles.css` заданы ground `#f2f2f3`, текст `#1d1f20` и полный OKLCH-рамп акцента. Недостающее — отображение прикладных ролей (граница объекта, утопленная поверхность, фон панели вставки, номера строк) на светлые эквиваленты тем же шагом шкалы. Это отдельная задача дизайна, и до неё переключатель темы из `US-E8-01` работает только в положении «тёмная».
