== Записи

=== SL-1 — тема проекта · 2026-08-17 · закрывает TC-1, TC-2, TC-3, TC-7, TC-8, TC-10

Сделано::
Набор из 22 ролей палитры (`AdocColors`), тёмная схема, отображение ролей на цветовую схему Material, формы без скругления, тема `AdocTheme`.
`App` переведён на роли. Окно Android получило тёмную тему до старта Compose, системные панели — явный тёмный стиль.
`TC-8` реализован задачей сборки `verifyNoColorLiterals`, входящей в `check`; её срабатывание проверено подсадкой нарушения.

Отступления от плана::
Добавлен `TC-10` — отображение ролей на схему Material. В спеке его не было: без него `MaterialTheme` подставляет светлую схему по умолчанию, и любой компонент Material оказался бы светлым.
Аналитика правлена, критерий записан.
+
`TC-3` уточнён: `RectangleShape` неприменим, прямоугольность выражается нулевым радиусом; три слота `Shapes` из восьми недоступны публично и остаются скруглёнными. Уточнение внесено и в описание дизайна.

Осталось незакрытым::
Проверка `TC-2` и `TC-7` идёт сверкой значений, а не запуском композиции: в `commonTest` нет `compose.uiTest`.
Это ограничение, а не пропуск — заведено открытым вопросом ниже.

Ревью::
Раундов: 1. Линзы: соответствие спеке, соответствие правилам, корректность.
Находок принято 10, все починены: схема Material из ролей, `contentColor` у `Surface`, `TC-7` по букве критерия, `TC-2` с наблюдаемым следствием, `asMap` перенесён в тесты, имена тестов латиницей, `@ReadOnlyComposable`, `TC-8` задачей сборки, тёмное окно, стиль системных панелей.
Отклонено 1 с обоснованием: неполнота `Shapes` — ограничение Material3, а не дефект кода; зафиксирована в документации.

Стиль::
Кодстайл Kotlin в проекте не заведён осознанно, сверка шла с `CLAUDE.md` и правилами разработки. Автоформатирование IDE не запускалось.
