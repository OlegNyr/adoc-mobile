== Этапы

[cols="1,2,1,2", options="header"]
|===
| Этап | Цель (наблюдаемая) | Слайсы | Выходной критерий

| E1
| Файл открывается, правится и сохраняется сам; правки не теряются
| SL-1…SL-4
| Реальный `.adoc` с устройства открыт, поправлен, сохранён; после выгрузки приложения текст на месте

== Границы работ

✅ Всегда::
Тест раньше кода.
Логика, которую можно проверить без устройства, живёт в `commonMain` и проверяется в `commonTest`.
Утверждение о поведении платформы подтверждается прогоном, а не памятью.

⚠️ Спросить::
Расширение платформенного шва сверх чтения, записи и удержания разрешения.
Любое поведение, при котором правки пользователя могут быть потеряны или перезаписаны.
Новая зависимость.

🚫 Никогда::
Своё undo вместо встроенного (`FR-10`).
Копирование файла пользователя в песочницу приложения.
Платформенные типы файлового доступа в модели документа.
Молчаливая потеря или перезапись правок.
Коммит при красном прогоне.

== Риски и точки перепланирования

* Встроенная история отмены может повести себя иначе при обновлении Compose → страховка в `TC-12`; сломается он — решение пересматривается, а не подпирается.
* Приём «временный файл и замена» может не работать для SAF-URI → выяснится на `SL-4`; тогда требование к атомарности переформулируется, а не тихо опускается.
* Чтение файла на 1000 строк может оказаться заметно медленным → выяснится на `SL-2`; тогда добавляется индикатор загрузки, отдельным слайсом.
