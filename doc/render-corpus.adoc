[.lead]
Тестовый корпус документов AsciiDoc и оснастка, которая сверяет вывод движка на устройстве с эталонным десктопным Asciidoctor.
Это задача `T-037` из xref:tasks.adoc[плана работ]; после xref:research/render-stack.adoc[разведки движка рендера] она выбирает версию ядра, а не подтверждает результат в конце.

toc::[]

== Зачем

Критерий успеха MVP — «превью совпадает с выводом десктопного Asciidoctor на тестовом корпусе».
Пока Asciidoctor.js был транспиляцией Ruby через Opal, совпадение обеспечивалось происхождением кода.
Ветка 4.x — самостоятельная реализация на JavaScript, выпущенная в июне 2026, и заявлений о проценте совместимости у неё нет.
Значит совпадение нужно измерять, а не предполагать.

Корпус отвечает на один вопрос: *чем вывод кандидата отличается от эталона и приемлемо ли это отличие*.

== Где лежит

Корпус и оснастка — в `testdata/render-corpus/`, вне `doc/`.

Причина: это фикстуры и код, а не документация.
Документы корпуса намеренно содержат пограничные конструкции, написаны без обязательной шапки и не подчиняются xref:documentation-rules.adoc[правилам ведения документации] — держать их рядом с продуктовыми документами значит либо ломать правила, либо ломать корпус.
Вдобавок CI собирает `doc/**/*.adoc` с падением на предупреждениях, и корпус попал бы под эту проверку без всякой пользы.

[source,text]
----
testdata/render-corpus/
├── src/                    корпус: 18 документов и каталог partials/
│   └── partials/           файлы для include:: и картинка для image::
├── expected/               эталонный HTML от Ruby Asciidoctor 2.0.26
│   ├── _manifest.json      версия движка, опции прогона, контрольные суммы
│   └── _warnings.log       предупреждения эталонного прогона, если были
├── tools/
│   ├── corpus.py           снятие эталона, канонизация, сравнение
│   └── render-actual.mjs   прогон корпуса через Asciidoctor.js на Node
└── build/                  результаты сравнения (не версионируется)
----

== Как снимается эталон

[,bash]
----
python testdata/render-corpus/tools/corpus.py reference
----

Эталон снимается локальным Ruby-Asciidoctor 2.0.26 и кладётся в `expected/`.
Вывод берётся из стандартного потока: безопасный режим не даёт писать за пределы базового каталога.

Опции прогона зафиксированы в одном месте — константа `RENDER_OPTIONS` в `corpus.py` — и повторены в `expected/_manifest.json`:

[cols="1,1", options="header"]
|===
| Опция | Значение

| backend | `html5`
| doctype | `article`
| standalone | нет, только тело документа
| safe mode | `safe`
| base dir | `src/`
| атрибуты из командной строки | ни одного
|===

Отсутствие обёртки важно дважды: так сравнивается разметка, а не встроенная таблица стилей на 130 КБ, и так же работает продукт — рендерер отдаёт `WebView` готовый фрагмент.
Ни одного атрибута снаружи не задаётся, чтобы паритет конфигураций сводился к четырём строчкам, которые нельзя случайно разойтись.

Манифест хранит контрольные суммы исходников и HTML: если корпус правили, а эталон не переснимали, это видно.

== Как сравнивается

Побайтовое сравнение HTML утонуло бы в шуме, поэтому оба вывода приводятся к *канонической форме* — потоку событий, по одному на строку.
Форма читаемая, поэтому обычный `diff` по ней сразу показывает, что именно разошлось.

Что гасится при канонизации:

Порядок и запись атрибутов:: атрибуты сортируются по имени, кавычки снимаются разбором, значение нормализуется по пробелам.
Порядок классов:: значение `class` разбивается на токены и сортируется — множество классов значимо, порядок нет.
Кодировка сущностей:: `+&#8217;+`, `+&rsquo;+` и сам символ становятся одним и тем же текстом; то же для `+&lt;+` против `+&#60;+`.
Незначащие пробелы:: пробельный текст между блочными элементами выбрасывается, внутри текстового узла схлопывается в один пробел, по краям блочных границ обрезается.
Форма пустых тегов:: `+<br>+`, `+<br/>+` и висящий `+</br>+` неразличимы.
HTML-комментарии:: выбрасываются.
Округление дробей:: числа с пятью и более знаками после запятой округляются до четырёх — разница вычисления ширины колонки не значима.
Изменчивое содержимое:: тег генератора и подвал с датой сборки удаляются.

Что *не* гасится и потому ловится:

* пробел между строчными элементами — он значим и его пропажа видна;
* любой текст внутри `+<pre>+`, включая отступы: дословный блок сравнивается как есть;
* имена тегов, набор классов, все прочие атрибуты, сгенерированные идентификаторы и цели ссылок.

Проверено намеренной порчей эталона: восемнадцать файлов с перемешанными атрибутами, переставленными классами, другой записью сущностей, лишними переводами строк, самозакрывающимися тегами и посторонним комментарием дают ноль расхождений.
Пять внесённых смысловых правок — подмена тега, изменённый отступ внутри `+<pre>+`, другой сгенерированный идентификатор, пропавший пробел между ссылками и изменённый `colspan` — ловятся все пять.

=== Уже разобранные системные расхождения

Флаг `--fold-presentational` сводит к одной форме два расхождения, которые уже разобраны вручную и признаны косметическими: устаревший презентационный атрибут `width` на `+<col>+` и `+<table>+` вместо `style="width: …"`, и разрыв страницы классом вместо инлайнового стиля.
По умолчанию флаг выключен: гасить расхождение можно только осознанно, поштучно и с записью причины здесь.

== Как пользоваться

[,bash]
----
# 1. снять эталон (нужен локальный asciidoctor)
python testdata/render-corpus/tools/corpus.py reference

# 2. получить вывод проверяемого движка в каталог с теми же именами файлов
#    (см. следующий раздел)

# 3. сравнить
python testdata/render-corpus/tools/corpus.py compare --actual build/actual-node
python testdata/render-corpus/tools/corpus.py compare --actual build/actual-node --fold-presentational

# посмотреть каноническую форму одного файла
python testdata/render-corpus/tools/corpus.py normalize expected/07-tables-basic.html
----

Оснастка написана на стандартной библиотеке Python, внешних зависимостей нет.
`compare` печатает сводку и профиль расхождений по конструкциям, а в каталог отчёта кладёт `summary.txt`, по файлу `.diff` на каждое расхождение и каноническую форму обоих выводов.
Код возврата `1`, если что-то разошлось или вывода не хватает, — команда годится как шаг CI.

Требование к проверяемому движку одно: HTML каждого документа корпуса лежит в файле с тем же именем и расширением `.html`.

== Первый прогон: Asciidoctor.js 4.0.9

Эталон снялся чисто: 18 файлов, ноль ошибок, ноль предупреждений Asciidoctor.

Вывод 4.0.9 снят на настольном Node тем же корпусом и теми же опциями.
Все 18 документов конвертировались без ошибок; расхождений с эталоном — четыре класса.

[cols="2,3,1", options="header"]
|===
| Класс | Суть | Оценка

| Ширина колонок и таблиц
| Вместо `style="width: 50%;"` на `+<col>+` и `+<table>+` выводится устаревший атрибут `width="50%"`
| косметика, гасится флагом

| Разрыв страницы
| Вместо `+<div style="page-break-after: always;">+` выводится `+<div class="page-break">+`
| косметика, гасится флагом

| Passthrough-макрос
| `+pass:[<em>текст</em>]+` экранирует разметку вместо того, чтобы пропустить её сырой
| дефект

| Нумерация сносок
| Сноски внутри пункта списка и ячейки таблицы получают номера из отдельной последовательности; в выводе появляются два `+<div class="footnote">+` с одинаковым `id` и ссылки ведут не туда
| дефект
|===

После гашения двух косметических классов 15 документов из 18 совпадают с эталоном полностью, а расхождения остаются ровно в трёх и сводятся к двум дефектам выше.

[IMPORTANT]
Это результат на настольном Node, а не на устройстве.
Он говорит о самой реализации Asciidoctor.js и ничего не говорит о связке «движок плюс QuickJS»: прогон на стенде остаётся обязательным.

== Как получить вывод 4.x

=== На настольном Node

Быстрый путь, устройство не нужен:

[,bash]
----
npm install asciidoctor@4.0.9
node testdata/render-corpus/tools/render-actual.mjs build/actual-node
----

Переменная `CORPUS_SRC` задаёт каталог корпуса, если скрипт запускается не из репозитория, — так `node_modules` можно держать вне рабочего дерева.
Скрипт печатает, какой формой API он воспользовался: экспорт называется `convert`, `getCoreVersion()` при этом возвращает `2.0.26`, а атрибут `asciidoctor-version` в документе — `4.0.9`.

=== На Android-стенде

Стенд проверяет то, чего настольный прогон не проверяет: работает ли бандл под QuickJS после правок, описанных в xref:research/render-stack.adoc[разведке движка рендера], и укладывается ли конвертация в бюджеты времени и памяти.

От стенда нужно одно: положить HTML каждого документа корпуса в файл с тем же именем, забрать каталог с устройства и запустить `compare`.
Опции конвертации обязаны совпадать с манифестом; иначе сравниваются конфигурации, а не реализации.

== Чего оснастка не проверяет

Это не полный список отличий движков, а инструмент с известными границами.

Внешний вид:: сравнивается разметка, а не то, как она выглядит.
Совпадение HTML не означает, что превью читаемо на телефоне; за это отвечает CSS тёмной темы, задача `T-035`.

Стандартную обёртку документа:: рендер идёт без обёртки, поэтому шапка, встроенные стили, подвал и оглавление в шапке не сравниваются.
Продукт их не использует.

Производительность:: ни времени конвертации, ни пика памяти корпус не измеряет.
Документы маленькие и подобраны по разнообразию конструкций, а не по объёму; поведение на 2–3 тыс. строк — отдельная задача.

Расширения:: `asciidoctor-kroki` в корпусе не участвует.
Диаграммные блоки остаются листингами, и именно это сравнивается.

Сообщения об ошибках:: предупреждения и ошибки движка при разборе кривого документа не сверяются, корпус синтаксически корректен.

Порядок классов, кодировку сущностей и незначащие пробелы:: они сознательно погашены канонизацией.
Если однажды понадобится побайтовая сверка, у `compare` есть режим `--raw`.

Сетевые пути:: `include::` по URI, удалённые изображения и любые обращения к сети из корпуса исключены — на мобильном этот путь всё равно отрезан.
