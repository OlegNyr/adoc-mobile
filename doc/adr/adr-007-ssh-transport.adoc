== Контекст

Видение фиксирует JGit на Android, но SSH-транспорт JGit существует в двух вариантах: исторический `org.eclipse.jgit.ssh.jsch` (JSch) и официальный `org.eclipse.jgit.ssh.apache` (Apache MINA sshd).
Выбор влияет на поддерживаемые типы ключей (`FR-27`), зависимость в каталоге версий и объём платформенного кода.
Развилка техническая: пользовательского выбора здесь нет, но зависимость новая, поэтому решение записывается, а не принимается молча.

== Решение

SSH-транспорт — `org.eclipse.jgit.ssh.apache` (Apache MINA sshd) той же версии, что и JGit.
`known_hosts` ведётся в приватной директории приложения; неизвестный или сменившийся host key подтверждается пользователем (`FR-29`).

== Альтернативы

* *`org.eclipse.jgit.ssh.jsch` (JSch)* — отвергнут: README бандла объявляет его deprecated и «essentially unmaintained» с правом удаления в любой момент; JSch не поддерживает ed25519 — современный тип ключа по умолчанию (источники — в xref:../research.adoc[разведке]).
* *Сторонняя SSH-библиотека (sshj и т. п.) со своей интеграцией в JGit* — отвергнута: свой транспортный код против готовой официальной интеграции, выигрыша нет.

== Последствия

Плюсы:: Современные ключи (ed25519, ECDSA-384/521); официальная поддерживаемая ветка JGit; прецедент работы на Android (orgzly, API ≥ 26 — совпадает с нашим `minSdk`).
Минусы и плата:: Дополнительная зависимость с собственным графом (`sshd-osgi`/`sshd-core`); работоспособность связки JGit 7.x + sshd на ART проверяется спайком H1 вместе с самим JGit.
Что теперь придётся поддерживать:: Версию sshd в связке с версией JGit в каталоге; UI подтверждения host key и хранение `known_hosts`.
