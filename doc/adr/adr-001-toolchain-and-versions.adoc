== Контекст

Проект стартует с нуля: кода нет, сборки нет.
Задача `T-001` держит весь граф работ — пока способ сборки и версии не закреплены, свободных задач в плане ноль.

Требование владельца: брать самые свежие *релизные* версии; ночные сборки, EAP, alpha, beta и RC не рассматривать.

Версии проверены по реестрам 2026-08-16, а не по памяти.
Отдельная деталь: в метаданных Google Maven поле `<release>` для AGP указывает на `9.4.0-alpha08` — доверять ему нельзя, стабильная версия отбирается фильтрацией списка.

== Решение

Сборка — Gradle, скрипты пишем руками с version catalog (`gradle/libs.versions.toml`).
Версии закреплены явно:

[cols="2,1,3", options="header"]
|===
| Компонент | Версия | Обоснование выбора именно этой

| Kotlin
| 2.4.10
| Последняя релизная; 2.4.20 существует только как Beta1, Beta2 и RC

| Compose Multiplatform
| 1.11.1
| Последняя релизная; 1.12.0 дошёл только до rc01

| Android Gradle Plugin
| 9.3.1
| Последняя релизная; 9.4.0 представлен только альфами

| Gradle
| 9.7.0
| `services.gradle.org/versions/current` с флагами `snapshot: false`, `nightly: false`

| JDK
| 21 (Azul 21.0.10)
| Установлен локально и указан в `JAVA_HOME`; AGP 9.3 требует не ниже 17
|===

Ограничения, подтверждённые документацией, а не предположением:

* AGP 9.3 требует Gradle не ниже 9.5.0, JDK не ниже 17, SDK Build Tools 36, максимальный API 37.
* JetBrains заявляют, что последняя версия Compose Multiplatform всегда совместима с последней версией Kotlin и выравнивать их вручную не нужно.

== Альтернативы

* *KMP-визард* — отвергнут: генерирует ровно тот же Gradle, но со своими версиями, которые всё равно пришлось бы переписывать под требование «только релизные». Непрозрачен: непонятно, что и почему попало в проект.
* *Оставить версии плавающими* (`latest.release`, динамические диапазоны) — отвергнут: воспроизводимость сборки важнее автоматических обновлений, а требование «без ночных сборок» с плавающими версиями не гарантируется в принципе.

== Последствия

Плюсы:: сборка воспроизводима; каждая версия поднята осознанно и с записанным основанием; переход на новую версию становится отдельным решением, а не побочным эффектом.
Минусы и плата:: за совместимостью следим сами; обновление версий требует повторной проверки той же связки AGP — Gradle — JDK.
Что придётся поддерживать:: version catalog как единственное место, где живут версии; при обновлении — перепроверка ограничений AGP по Gradle и JDK.

== Открытый пункт

Android SDK на машине разработки не установлен: `ANDROID_HOME` и `ANDROID_SDK_ROOT` пусты, каталога SDK нет.
Это предусловие задачи `T-003`, а не развилка: SDK ставится через Android Studio или command-line tools, нужен API 36 и Build Tools 36.
