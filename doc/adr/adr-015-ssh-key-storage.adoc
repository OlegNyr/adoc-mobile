== Контекст

Владелец решил `OQ-3`: SSH-ключ генерируется в приложении, приватная часть устройство не покидает.
Оставался технический вопрос: держать приватный ключ *неизвлекаемым в Android Keystore* или файлом в хранилище секретов фичи (файл + AES-GCM-ключ из Keystore, решение `OQ-2`).

Разведка формулировала гипотезу `H4` — «Keystore не подписывает ed25519».
Спайк `SL-15` проверил её фактами на устройстве (Samsung SM-S948B, Android 16, API 36) — см. xref:../features/007-git-sync/research.adoc#spike-e4[раздел «Спайк E4»].

== Решение

Приватный ключ генерируется обычным провайдером JCA в памяти процесса и сохраняется *файлом, зашифрованным AES-GCM-ключом из Android Keystore* — тем же хранилищем секретов, что и токен HTTPS (`OQ-2`).
В Android Keystore приватный ключ не заводится.

== Почему не Keystore

Исходная формулировка `H4` неверна: ключ генерируется и подписывает.
Но опереться на этот путь нельзя по трём независимым причинам, каждая достаточна сама по себе:

. *Формат подписи.* Keystore отдаёт 72 байта в DER-обёртке (`SEQUENCE`), протокол SSH требует сырые 64 байта `R||S`.
Понадобилась бы своя конвертация внутри рукопожатия.
. *Интеграция с MINA sshd.* Библиотека подписывает рукопожатие сама и ожидает обычный `KeyPair` с доступным материалом; неизвлекаемый ключ потребовал бы собственного адаптера подписи — свой криптокод в самом чувствительном месте.
. *Пол по API.* Проект держит `minSdk 26`, а ed25519 в Keystore — свойство свежих версий Android: на большинстве поддерживаемых устройств генерация просто откажет, и второй путь всё равно нужен.
Подпись к тому же работает только при `setDigests(DIGEST_NONE)`; с `DIGEST_SHA512` и без явного digest Keystore отвечает `Incompatible digest`.

== Альтернативы

* *Ключ в Keystore + свой адаптер подписи для sshd* — отвергнут: собственный криптокод в рукопожатии против готовой библиотеки, при этом на `minSdk 26` всё равно нужен запасной путь.
* *Ключ в Keystore на новых API, файл на старых* — отвергнут: две ветки хранения удваивают поверхность ошибок ради выигрыша, который пользователь не видит.

== Последствия

Плюсы:: Один путь на все поддерживаемые версии Android; MINA sshd работает штатным API; ключ шифруется тем же проверенным хранилищем, что и токен (`TC-30`).
Минусы и плата:: Приватный ключ существует в памяти процесса на время операции и лежит на диске шифртекстом — при компрометации устройства с извлечением ключа Keystore он защищён слабее, чем неизвлекаемый.
Принято сознательно: сценарий фичи — рабочий телефон инженера, а не защита от криминалистического извлечения.
Что придётся поддерживать:: Формат сериализации ключа в хранилище и его совместимость при обновлениях приложения.
