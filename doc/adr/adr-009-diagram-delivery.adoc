== Контекст

Расширение отдаёт `+<img src="https://kroki.io/plantuml/svg/…">+` — внешний адрес в HTML, который показывает `WebView`.
Наше превью устроено ровно наоборот: `javaScriptEnabled = false`, `blockNetworkLoads = true`, а всё, что не локальная картинка документа, перехват отдаёт пустым ответом (`AdocPreview.android.kt`, `PreviewImages.kt`).
То есть без решения диаграмма не покажется никак.

Кто именно ходит в сеть — это и выбор архитектуры, и выбор поверхности безопасности, и выбор того, сколько кода придётся написать второй раз для iOS.

== Решение

Диаграммы разрешаются *в общем коде до показа страницы*, в шве `page: suspend (fragment) -> String` у `PreviewPipeline`.
Общий код находит в HTML адреса Kroki, спрашивает кэш, при промахе — сетевой транспорт (интерфейс в `commonMain`, реализация на платформе), и переписывает `src` на локальный адрес в зоне `PREVIEW_BASE_URL`, откуда байты отдаёт уже существующий перехватчик.
`WebView` внешних адресов не видит: `blockNetworkLoads` остаётся включённым, поверхность превью не меняется.

Пока диаграмма не пришла, страница публикуется с плейсхолдером; приход изображений — повод перерисовать превью, как это уже делает поколение рендера.

== Альтернативы

* *`WebView` грузит адрес сам* (снять `blockNetworkLoads`) — отвергнута: это снимает единственный рубеж, отделяющий недоверенный документ пользователя от сети. Любой `+<img src="http://…">+`, написанный в документе, стал бы сетевым запросом, а кэш и режим «ВЫКЛ» пришлось бы навязывать через тот же перехват, то есть работа всё равно возвращается к нам — но уже без гарантии.
* *Сеть внутри платформенного перехватчика* (`shouldInterceptRequest` ходит на Kroki) — отвергнута: логика режимов, кэша, таймаутов и деградации переехала бы в `androidMain` и была бы написана заново для `WKWebView`; проектная цель — ≥80 % общего кода, а `verifyRenderSeams` прямо запрещает третий платформенный шов. Плюс отказ там нечем показать: подменить `img` на блок с исходным кодом перехватчик уже не может.
* *Сеть внутри движка* (полифил `fetch` в QuickJS, мост в Kotlin) — отвергнута: конвертация стала бы сетевой операцией, её таймаут (5 с, `FR-11` фичи 003) смешался бы с сетевым, а отмена рендера при наборе рвала бы загрузки. Движок остаётся чистой функцией «текст → HTML».

== Последствия

Плюсы:: Вся логика — режимы, кэш, деградация, таймауты — в `commonMain` и тестируется без устройства. Превью не получает ни новой поверхности, ни новых прав. iOS достаётся только реализация транспорта.
Минусы и плата:: Появляется этап разбора и правки HTML между конвертером и показом — работа со строкой разметки, а не с деревом; правило «фрагмент вставляется как есть» из фичи 003 придётся ослабить и оговорить. Превью публикуется дважды: с плейсхолдерами и с картинками.
Что теперь придётся поддерживать:: Правило распознавания адресов Kroki в HTML и его устойчивость к обновлению расширения — на это заводится тест на корпусе.
