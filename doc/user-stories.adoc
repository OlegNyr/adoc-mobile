== Как читать этот документ

Роли::
*Инженер* — разработчик или техписатель в docs-as-code процессе (Git + AsciiDoc + CI).
*Автор заметок* — ведёт личную базу знаний в `.adoc`, без Git.
*Читатель* — открывает чужой `.adoc` для просмотра, не редактирует.

Идентификаторы::
`US-<эпик>-<номер>`. Идентификатор неизменен: истории не перенумеровываются при вставке новых.

Этап::
`MVP` — входит в первый выпуск. `IT2`, `IT3` — следующие итерации в порядке приоритета.
Границы этапов заданы в разделе «Продуктовый скоуп» видения и здесь не переопределяются.

Критерии приёмки::
Формулируются как проверяемое поведение. Числовые пороги берутся из раздела «Критерии успеха MVP» видения.

== Эпик E1. Работа с файлами

[[US-E1-01]]
=== US-E1-01. Открыть `.adoc` из хранилища устройства (MVP)

*Как* автор заметок, *я хочу* открыть `.adoc`-файл через системный файловый диалог, *чтобы* работать с документом там, где он уже лежит, не импортируя его в приложение.

Критерии приёмки::
* Открытие идёт через SAF на Android и document picker на iOS — своего файлового менеджера у приложения нет.
* Выданный доступ переживает перезапуск приложения (persistable tree URI / security-scoped bookmark).
* Файл в кодировке UTF-8 с любым типом переводов строк открывается без искажения; исходный тип переводов строк сохраняется при записи.
* Файл примерно на 1000 строк открывается и становится доступен для ввода без блокировки UI (размер сужен по итогам замеров, см. xref:adr/adr-004-document-size-limit.adoc[ADR-004]).

[[US-E1-02]]
=== US-E1-02. Автосохранение (MVP)

*Как* автор заметок, *я хочу*, чтобы правки сохранялись сами, *чтобы* не терять текст при сворачивании или выгрузке приложения системой.

Критерии приёмки::
* Правки сохраняются по паузе ввода и при уходе приложения в фон.
* Заголовок экрана показывает состояние документа: `ИЗМЕНЁН · НЕ СОХРАНЁН` — до записи, чистое имя файла — после.
* Отказ записи (нет прав, нет места) показывается как ошибка с сохранением несохранённого текста в памяти — молчаливой потери правок не происходит.

[[US-E1-03]]
=== US-E1-03. Undo/redo (MVP)

*Как* автор заметок, *я хочу* отменять и повторять правки, *чтобы* безопасно экспериментировать с текстом.

Критерии приёмки::
* Undo/redo доступны из меню документа и с аппаратной/системной клавиатуры.
* Шаг отмены группирует непрерывный ввод, а не отдельный символ.
* Вставка конструкции с панели (<<US-E4-01>>) — один шаг отмены.

[[US-E1-04]]
=== US-E1-04. Навигация по файлам репозитория (IT2)

*Как* инженер, *я хочу* видеть дерево файлов открытой папки со статусом Git, *чтобы* переходить между документами, не выходя в файловый менеджер.

Критерии приёмки::
* Список показывает файлы и папки, метку статуса Git (`M`, `A`, `?`), путь и время последней правки — см. макет «01 · Репозиторий».
* Фильтры `ИЗМЕНЁННЫЕ` / `ВСЕ ФАЙЛЫ` / `НЕДАВНИЕ` переключают состав списка.
* Для папки показывается число вложенных файлов.

[[US-E1-05]]
=== US-E1-05. Поиск по документу (IT3)

*Как* инженер, *я хочу* искать текст в открытом документе, *чтобы* быстро находить нужный фрагмент в длинной странице.

Критерии приёмки::
* Поиск подсвечивает совпадения и позволяет переходить между ними.
* Позиция каретки после выхода из поиска остаётся на выбранном совпадении.

== Эпик E2. Редактор и подсветка

[[US-E2-01]]
=== US-E2-01. Подсветка синтаксиса (MVP)

*Как* автор заметок, *я хочу* видеть структуру документа цветом, *чтобы* различать разметку и текст без рендера.

Критерии приёмки::
* Подсвечиваются: заголовки, атрибуты документа (`:status:`), списки, delimited-блоки (listing, example, sidebar, comment), инлайн-форматирование, ссылки и макросы.
* Подсветка применяется к отображению и не меняет содержимое буфера: копирование даёт исходный текст с разметкой.
* Задержка от ввода до перекраски — не более 100 мс на документе примерно в 1000 строк; стили ставятся только для видимого окна.
* При правке пересчитывается только затронутый участок, а не весь документ.

[[US-E2-02]]
=== US-E2-02. Ввод без сюрпризов (MVP)

*Как* автор заметок, *я хочу* обычное поведение клавиатуры, *чтобы* печатать так же, как в любом другом мобильном приложении.

Критерии приёмки::
* Работают IME и композиция символов, автокоррекция, выделение, буфер обмена, перетаскивание каретки.
* Прокрутка следует за кареткой; каретка не уезжает под клавиатуру или под панель вставки.
* Ввод на документе примерно в 1000 строк идёт без пропуска кадров.

[[US-E2-03]]
=== US-E2-03. Номера строк и позиция каретки (IT3)

*Как* инженер, *я хочу* видеть номера строк и текущую позицию, *чтобы* соотносить документ с выводом сборки и обсуждать его с коллегами.

Критерии приёмки::
* Колонка номеров включается в настройках; номер текущей строки выделен акцентом.
* В заголовке экрана показывается позиция каретки в формате `Л14 · С22` — см. макет «1b · Редактор + панель превью».

[[US-E2-04]]
=== US-E2-04. Настройки внешнего вида редактора (IT2)

*Как* автор заметок, *я хочу* настроить размер шрифта и перенос строк, *чтобы* подогнать редактор под свой экран и зрение.

Критерии приёмки::
* Размер шрифта редактора меняется слайдером и показан числом в pt.
* Мягкий перенос строк включается и выключается; при выключенном переносе доступна горизонтальная прокрутка.
* Настройки переживают перезапуск.

[[US-E2-05]]
=== US-E2-05. Видеть проблемы документа (IT2)

*Как* инженер, *я хочу* видеть список проблем документа, *чтобы* не искать причину сломанного превью глазами по всему файлу.

Критерии приёмки::
* Сообщения снимаются с логгера Asciidoctor в том же проходе, что и превью; отдельного прохода проверки нет.
* Ловятся как минимум: неразрешённый `include`, ссылка на несуществующий якорь, незакрытый delimited-блок, неопределённый атрибут, перескок уровня заголовка, дублирующийся id.
* Показываются только уровни `ERROR` и `WARN`; стилистические замечания не показываются.
* Над панелью вставки — строка со счётчиком проблем; по касанию открывается список, по выбору — переход на строку.
* У сообщения есть номер строки; движок для этого запускается с `sourcemap`.
* Наличие проблем не блокирует ни ввод, ни рендер: превью строится всегда, диагностика только сопровождает.
* При нулевом числе проблем строка не занимает место на экране.

[[US-E2-06]]
=== US-E2-06. Отметки проблем в редакторе (IT3)

*Как* инженер, *я хочу* видеть проблему на самой строке, *чтобы* понимать причину, не открывая список.

Критерии приёмки::
* Метка уровня ставится в колонке номеров строк; история зависит от <<US-E2-03>> и без неё не реализуется.
* Проблемный фрагмент помечается подчёркиванием или подложкой средствами существующей подсветки. Волнистое подчёркивание не используется: `TextDecoration` в Compose его не умеет, а рисование поверх текста бьёт по самой хрупкой части раскладки.
* Быстрые структурные проверки (незакрытый блок, несовпавшая длина ограничителей, скачок уровня заголовка) приходят от сканера подсветки в его собственном дебаунсе, не дожидаясь рендера.
* Блок, внутри которого стоит каретка, не проверяется: незакрытый блок не помечается ошибкой, пока его печатают.
* Отметки обновляются по паузе ввода, а не на каждый символ.

[[US-E2-07]]
=== US-E2-07. Проверка орфографии (IT3)

*Как* техписатель, *я хочу* видеть опечатки в тексте, *чтобы* не отправлять коллегам документ с ошибками.

Критерии приёмки::
* Словарь берётся у платформы (`SpellCheckerSession` на Android, `UITextChecker` на iOS); своего словаря приложение не везёт.
* Не проверяются: код-блоки, инлайн-моноширинный текст, имена и значения атрибутов, URL, цели макросов и ссылок, пути файлов. Границы даёт сканер подсветки.
* Проверка отключается в настройках целиком.
* Автокоррекция и подсказки клавиатуры к этой истории не относятся — они работают и без неё (<<US-E2-02>>).
* Смешанный русско-английский текст не даёт сплошного потока ложных срабатываний; если приемлемого качества достичь не удаётся, фича не выпускается — плохая проверка хуже её отсутствия.

== Эпик E3. Превью

[[US-E3-01]]
=== US-E3-01. Живое превью (MVP)

*Как* автор заметок, *я хочу* видеть отрендеренный документ рядом с исходником, *чтобы* проверять результат, не выходя из редактора.

Критерии приёмки::
* Превью строится настоящим Asciidoctor: таблицы, admonitions, блоки кода, атрибуты документа выглядят как в десктопном пайплайне.
* Рендер запускается по паузе ввода (~300 мс), а не на каждый символ, и не блокирует ввод.
* Рендер работает без сети.
* Ошибка рендера показывается в превью сообщением, редактор при этом остаётся рабочим.

[[US-E3-02]]
=== US-E3-02. Переключение «Редактор ↔ Превью» (MVP)

*Как* автор заметок, *я хочу* переключаться между исходником и результатом одним касанием, *чтобы* не терять место в узком мобильном экране.

Критерии приёмки::
* Вкладки `РЕДАКТОР` / `ПРЕВЬЮ` переключают содержимое экрана; активная вкладка помечена акцентной линией — см. макет «02 · Редактор ↔ превью».
* Переключение не сбрасывает позицию каретки и состояние прокрутки редактора.
* На планшете доступен режим side-by-side.

[[US-E3-03]]
=== US-E3-03. Панель превью под редактором (IT2)

*Как* инженер, *я хочу* держать превью открытым под редактором, *чтобы* видеть результат правки сразу, без переключения вкладок.

Критерии приёмки::
* Панель вытягивается вверх жестом, свёрнутое состояние показывает начало документа.
* Заголовок панели показывает свежесть рендера (`обновлено 1 с назад`).
* Раскладка соответствует макету «1b · Редактор + панель превью».

== Эпик E4. Панель быстрой вставки

[[US-E4-01]]
=== US-E4-01. Вставка конструкций одним касанием (IT2)

*Как* автор заметок, *я хочу* вставлять разметку с панели над клавиатурой, *чтобы* не искать спецсимволы в мобильной раскладке.

Критерии приёмки::
* Панель стоит между текстом и клавиатурой и содержит минимум: `=`, `==`, `*B*`, `_I_`, `` `c` ``, список, `link`, `img`, кнопку раскрытия остальных.
* Кнопки прокручиваются горизонтально; кнопка раскрытия даёт доступ к таблице, admonition и блоку кода.
* При выделенном тексте инлайн-конструкция оборачивает выделение; без выделения — вставляется заготовка с кареткой внутри.
* Высота кнопок пригодна для пальца (не меньше 38 dp) — см. макет «02».

== Эпик E5. Git-синхронизация

[[US-E5-01]]
=== US-E5-01. Клонировать репозиторий (IT2)

*Как* инженер, *я хочу* склонировать репозиторий документации на устройство, *чтобы* работать с ним офлайн и коммитить из приложения.

Критерии приёмки::
* Форма принимает URL, способ авторизации (`SSH-КЛЮЧ` / `ТОКЕН` / `БЕЗ АВТ.`), ветку и целевую папку — см. макет «05 · Клонирование».
* Доступна опция поверхностного клона (`depth 1`).
* Во время клонирования показывается прогресс: процент, число объектов, скорость.
* Клон кладётся обычной папкой: другие приложения видят те же файлы.
* Секреты (токен, приватный ключ) хранятся в платформенном защищённом хранилище, а не в настройках приложения, и не попадают в логи.

[[US-E5-02]]
=== US-E5-02. Видеть состояние ветки (IT2)

*Как* инженер, *я хочу* видеть текущую ветку и расхождение с origin, *чтобы* понимать, нужно ли синхронизироваться перед правкой.

Критерии приёмки::
* Показаны имя ветки, счётчики `↓N ↑N`, число локальных изменений и адрес remote — см. макет «01».
* Значение счётчиков обновляется после pull и после commit.

[[US-E5-03]]
=== US-E5-03. Pull (IT2)

*Как* инженер, *я хочу* забрать изменения из origin, *чтобы* работать поверх свежей версии.

Критерии приёмки::
* Pull доступен с экрана репозитория одной кнопкой.
* Результат сообщается явно: обновлено, уже актуально или конфликт (<<US-E5-05>>).
* Открытый в редакторе файл, изменённый pull-ом, перечитывается; несохранённые локальные правки при этом не теряются.

[[US-E5-04]]
=== US-E5-04. Commit и push (IT2)

*Как* инженер, *я хочу* выбрать файлы, написать сообщение и отправить коммит, *чтобы* закрыть цикл docs-as-code без ноутбука.

Критерии приёмки::
* Экран коммита показывает индекс с чекбоксами, метку статуса и дифф-счётчики `+41 −6` — см. макет «03 · Commit / Push».
* Счётчик символов подсказывает длину первой строки сообщения (`50 / 72 симв.`).
* Переключатель «Отправить в origin после коммита» объединяет commit и push в одно действие.
* Неотслеживаемые файлы по умолчанию не включены в индекс.
* Отказ push (нет сети, нет прав, non-fast-forward) не откатывает уже сделанный локальный коммит и сообщается отдельно.

[[US-E5-05]]
=== US-E5-05. Разрешить конфликт (IT2)

*Как* инженер, *я хочу* выбрать нужную версию конфликтного участка, *чтобы* завершить слияние прямо на телефоне.

Критерии приёмки::
* Для каждого участка показаны локальная и удалённая версии с авторами и временем, а также предпросмотр результата — см. макет «04 · Конфликт».
* Доступны варианты `ЛОКАЛЬНОЕ` / `УДАЛЁННОЕ` / `ОБА`; выбранный вариант подсвечен, блок результата пересобирается сразу.
* Счётчик `1/2` показывает прогресс по участкам; завершить слияние можно только после разрешения всех.
* Полноценного построчного merge-редактора в этой итерации нет — это осознанное ограничение видения.

[[US-E5-06]]
=== US-E5-06. История изменений файла (IT3)

*Как* инженер, *я хочу* посмотреть историю правок документа, *чтобы* понять, кто и когда менял раздел.

Критерии приёмки::
* Для открытого файла доступен список коммитов с автором, датой и сообщением.
* Из списка можно посмотреть дифф выбранного коммита.

== Эпик E6. Диаграммы

[[US-E6-01]]
=== US-E6-01. Рендер диаграмм через Kroki (IT2)

*Как* инженер, *я хочу* видеть в превью отрендеренные PlantUML/Mermaid-диаграммы, *чтобы* проверять схемы вместе с текстом.

Критерии приёмки::
* Блоки `[plantuml]` / `[mermaid]` превращаются в изображения средствами asciidoctor-kroki.
* Пока изображение грузится, на его месте стоит заглушка-плейсхолдер с пометкой источника.
* Адрес Kroki-сервера настраивается; по умолчанию — публичный `kroki.io`.
* В настройках доступна проверка сервера с показом результата и задержки — см. макет «06 · Настройки».

[[US-E6-02]]
=== US-E6-02. Диаграммы офлайн (IT2)

*Как* инженер, *я хочу*, чтобы уже отрендеренные диаграммы были видны без сети, *чтобы* превью не разваливалось в дороге.

Критерии приёмки::
* Отрендеренные изображения кэшируются на устройстве; кэширование можно отключить в настройках.
* Без сети и без кэша блок показывается как исходный код диаграммы с явной пометкой, а не пустым местом или ошибкой.
* Содержимое диаграммы уходит на внешний сервер только при включённом режиме `KROKI` — режим `ВЫКЛ` полностью исключает сетевые обращения.

== Эпик E7. Экспорт и передача

[[US-E7-01]]
=== US-E7-01. Экспорт в PDF (IT3)

*Как* техписатель, *я хочу* получить PDF документа, *чтобы* отправить его тем, кто не работает с исходниками.

Критерии приёмки::
* PDF печатается платформенными средствами из того же HTML, что и превью.
* Применяется печатная тема: разрывы страниц по секциям, колонтитулы.
* Готовый файл уходит в системный share sheet.

[[US-E7-02]]
=== US-E7-02. Экспорт в standalone HTML (IT3)

*Как* техписатель, *я хочу* выгрузить самодостаточный HTML, *чтобы* переслать документ одним файлом.

Критерии приёмки::
* Стили встроены в файл; документ открывается без внешних ресурсов.
* Файл уходит в share sheet.

== Эпик E8. Настройки и оформление

[[US-E8-01]]
=== US-E8-01. Тёмная тема (MVP)

*Как* автор заметок, *я хочу* тёмное оформление, *чтобы* работать с текстом вечером и не слепнуть.

Критерии приёмки::
* Тёмная тема — оформление по умолчанию (см. xref:design/design.adoc[описание дизайна]).
* Выбор `ТЁМНАЯ` / `СВЕТЛАЯ` / `СИСТЕМА` доступен в настройках и переживает перезапуск.
* Превью следует выбранной теме, а не остаётся белым листом в тёмном интерфейсе.

== Эпик E9. Чтение

[[US-E9-01]]
=== US-E9-01. Открыть `.adoc` по интенту (IT3)

*Как* читатель, *я хочу* открыть `.adoc` из файлового менеджера или мессенджера, *чтобы* прочитать документ в нормальном виде, а не как простыню текста.

Критерии приёмки::
* Приложение регистрируется как обработчик `.adoc` и открывается сразу в режиме превью.
* Из режима чтения доступен переход к редактированию, если у приложения есть право на запись файла.

== Не реализуем осознанно

Эти пункты закрыты решением из видения; истории на них не заводятся:

* автодополнение и сворачивание блоков;
* WYSIWYG-режим;
* собственный парсер AsciiDoc;
* полноценный построчный merge-редактор в первой версии Git-слоя.
