== Главное: посылка видения устарела

Видение описывает Asciidoctor.js как транспиляцию Ruby через Opal и строит на этом решение «движок живёт синглтоном, потому что инициализация Opal-рантайма дорогая».

*Asciidoctor.js 4.0 выбросил Opal целиком.* Ветка вышла 2026-06-22, текущая версия 4.0.9 опубликована 2026-08-16.
Документация проекта: «no longer compiled from Ruby via Opal — the library is written in idiomatic, modern JavaScript (ESM)», «No runtime dependencies — no Opal, no Ruby, no generated bundle».

Что это меняет:

[cols="2,2,2", options="header"]
|===
| Свойство | Как в видении | Как есть

| Происхождение
| транспиляция Ruby через Opal
| самостоятельная реализация на JavaScript

| Бандл
| Opal-рантайм плюс код
| один ESM-файл 879 469 Б, без зависимостей

| API
| синхронный
| полностью асинхронный, `convert` возвращает промис

| Причина держать синглтон
| дорогая инициализация Opal
| разбор и выполнение ~880 КБ модуля
|===

Асинхронность — в нашу пользу: она ложится на контракт `suspend fun render(source: String): String` точнее, чем синхронный вызов.

== Риск совместимости, которого раньше не было

README пакета и сайт документации сообщают, что реализация 4.x сгенерирована из Ruby-исходников с помощью ИИ и отревьюена человеком.

Это бьёт прямо в критерий успеха MVP «превью совпадает с выводом десктопного Asciidoctor на тестовом корпусе».
Раньше эквивалентность обеспечивалась происхождением кода: это был буквально тот же Ruby, транспилированный.
Теперь это независимая реализация возрастом два месяца, и заявлений о проценте совместимости или о прогоне ruby-набора тестов разведка не нашла.

Вывод: xref:../tasks.adoc[`T-037`] — корпус сравнения с десктопным Asciidoctor — перестаёт быть приёмочной формальностью в конце и становится *инструментом выбора версии*. Его следует делать раньше, чем планировалось.

== Что нужно от движка

Разбор самого бандла показал требуемый уровень языка: `??=`, `?.`, `replaceAll`, lookbehind в регулярных выражениях, Unicode property escapes.
Node-специфики нет: `require` отсутствует, `process` и `Buffer` встречаются только в комментариях.
`fetch` используется для чтения `include::` по URI — на мобильном этот путь всё равно отрезается.

Значит нужен движок уровня ES2020+ с поддержкой Unicode-регекспов.
Rhino отпадает по этому критерию.

Отдельная проблема — *чистый ESM без UMD-сборки*.
Движку либо нужен загрузчик модулей, либо бандл придётся пересобирать в самодостаточный вид.

=== Основной кандидат: quickjs-kt

Единственный, кто закрывает сразу четыре условия:

* *корутинный `suspend` API по дизайну* — без выделенных потоков и ручной синхронизации;
* *411 КБ* против 25 МБ у V8-вариантов;
* *поддержка и Android, и iOS* одним KMP-API (заявлены `iosArm64`, `iosX64`, `iosSimulatorArm64`);
* ES-модули с кэшем байткода — то есть дорогой разбор бандла кэшируется.

Последний пункт важнее, чем кажется: если iOS-таргет действительно работает, *шов `expect`/`actual` для рендерера схлопывается в общий код*.
Видение планировало здесь два разных движка — QuickJS на Android и `JavaScriptCore` на iOS. Один KMP-движок убирает целый платформенный шов и напрямую работает на критерий «доля платформенного кода ≤ 20 %».

Риск кандидата — *bus factor равен единице*: 146 звёзд, один мейнтейнер.

=== Запасные

*Zipline* — тот же QuickJS, тот же порядок размера, мейнтейнер Cash App. Заточен под запуск Kotlin/JS-модулей, а не произвольного JS.

*androidx JavaScriptEngine* — ноль байт в APK, исполнение в отдельном песочном процессе, скорость V8. Но всё завязано на версию системного WebView, критичные возможности определяются через `isFeatureSupported()`, и на устройстве со старым WebView может не оказаться ни загрузки ES-модулей, ни обхода лимита транзакции binder — а без последнего бандл в 879 КБ туда не пролезет. Android-only, iOS не закрывает.

=== Снятые с рассмотрения

*Javet и J2V8* — не из-за размера (хотя 25 МБ и 12,5 МБ против 0,4 МБ несоразмерны для редактора документов), а из-за модели потоков.
Документация Javet прямо заявляет, что корутины и виртуальные потоки несовместимы с потоковой моделью V8 и вызов API из корутины приводит к падению JVM без дополнительной синхронизации.
У нас весь пайплайн построен на корутинах.
У J2V8 та же модель, плюс лицензия EPL-1.0 вместо Apache-2.0 и фактический режим поддержки: последний коммит 2025-11-14, 178 открытых issue.

*Rhino* — не дотягивает по уровню языка.
*Hermes* — публичного standalone-API вне React Native не найдено.

== Спайк: бандл запускается

*Проверено 2026-08-17: да, запускается.*

Способ проверки — выбрасываемый модуль с `quickjs-kt` 1.0.14 на JVM-таргете, тест загружает бандл и конвертирует документ с заголовком, admonition, блоком кода и таблицей.
JVM выбрана намеренно: движок под Android и под JVM один и тот же, а вопрос «выполняется ли код» от платформы не зависит.
Код спайка удалён после получения ответа, рецепт сохранён здесь.

=== Что потребовалось

Три правки, все механические и воспроизводимые скриптом:

. *`import.meta.url` заменяется на пустую строку.* Бандл вычисляет через него пути к каталогам файловой системы, но в режиме обычного скрипта `import.meta` — синтаксическая ошибка, то есть падение происходит на разборе. Блок уже обёрнут авторами в `try`/`catch` с комментарием «в браузере это будут пустые строки», поэтому подстановка пустой строки воспроизводит именно задуманное браузерное поведение. Четыре вхождения.
. *Финальный `export { … }` превращается в `globalThis.Asciidoctor = { … }`.* 52 имени, из них четыре — переименования вида `X as Y`, которые в объектном литерале записываются как `Y: X`. Это заменяет собой возню с загрузчиком модулей.
. *Полифил `TextEncoder`.* QuickJS — голый ES без веб-API, а Asciidoctor считает длину строки в байтах через `TextEncoder` в `_limitBytesize`. Без него конвертация падает на разборе атрибутов документа. Достаточно минимальной реализации кодирования UTF-8 с обработкой суррогатных пар.

Полезно также подставить заглушку `console`: движок его не имеет, и без заглушки диагностика получается невнятной.

== Замеры на устройстве (T-013)

Замерено 2026-08-17 на Samsung SM-S948B стендом `androidApp/src/debug/…/bench/RenderBench*`.
Бандл Asciidoctor.js 4.0.9 с патчами из спайка, quickjs-kt 1.0.14, движок на отдельном потоке со стеком 8 МБ.
Пять прогонов, ниже — медиана прогретых.

[cols="1,1,1,1,1", options="header"]
|===
| Строк | Символов | Инициализация | `convert`, медиана | Дебаунс 300 мс

| 1000 | 44 713 | 48,8 мс | *142,4 мс* | укладываемся
| 3000 | 134 654 | 45,7 мс | *413,9 мс* | не укладываемся
|===

Инициализация разбирается на части: чтение ассета ~7 мс, создание рантайма ~7 мс, выполнение 865 КБ скрипта ~33 мс.
Разовые 45–49 мс — это дёшево и подтверждает решение держать движок синглтоном.

Передача через границу практически бесплатна: JSON-сериализация исходника 1–3 мс, возврат HTML (94 КБ и 284 КБ) — 0,5–1,2 мс.
Строгая JSON-сериализация, которую требует архитектура, ничего не стоит.

Прогрева нет: первый прогон отличается от пятого на 5–7 %.
Кэш байткода проверять незачем — экономить нечего.

[IMPORTANT]
.Два риска закрылись одним решением
====
xref:../adr/adr-004-document-size-limit.adoc[ADR-004] сузил размер документа до ~1000 строк по итогам замеров *текстового поля*.
Рендер к тому решению отношения не имел — и попал в тот же порог: на 1000 строк укладываемся в дебаунс с запасом вдвое, на 3000 не укладываемся вовсе.

Это не совпадение, а следствие того, что оба ограничения линейны по размеру документа.
Но проверять стоило: если бы рендер упёрся раньше поля, `ADR-004` пришлось бы пересматривать.
====

== Сравнение версий ядра: дефекты и цена

Раздел добавлен 2026-08-17, когда корпус сверки (`T-037`) дал первые результаты.

=== Что нашёл корпус в 4.0.9

Прогон 18 документов корпуса через Asciidoctor.js 4.0.9 и эталонный Ruby Asciidoctor 2.0.26 дал четыре класса расхождений.
Два косметических — ширина колонок таблицы записывается атрибутом вместо инлайнового стиля, разрыв страницы оформлен классом вместо стиля.
Два — *настоящие дефекты*:

* `pass:[…]` экранирует разметку вместо того, чтобы пропустить её без подстановок;
* сноски внутри пункта списка и внутри ячейки таблицы нумеруются отдельной последовательностью, из-за чего в выводе появляются два блока сноски с *одинаковым* `id`, а ссылки ведут не туда.

После гашения косметики 15 документов из 18 совпадают полностью.

Это ровно тот риск, ради которого корпус поднимали наверх: 4.x — самостоятельная реализация, заявлений о совместимости у неё нет.

=== Цена перехода на 3.0.4

Замер обеих версий в одинаковых условиях (Node, V8, тот же генератор документа, что в стенде, медиана пяти прогретых прогонов):

[cols="1,1,1,1", options="header"]
|===
| Версия | Инициализация | 1000 строк | 3000 строк

| 3.0.4 | 142 мс | 38,6 мс | 108,4 мс
| 4.0.9 | 44,6 мс | 13,3 мс | 29,7 мс
|===

*3.0.4 медленнее примерно втрое*, и это ожидаемо: Opal транспилирует Ruby в JS, порождая много мелких вызовов.
Бандл тоже тяжелее — 1,7 МБ против 879 КБ (минифицированный 732 КБ).

Опасность в множителе. Замеры на устройстве показали, что QuickJS без JIT медленнее Node примерно в десять раз: 4.0.9 давал 13,3 мс на Node и 142 мс на телефоне.
Если коэффициент сохранится, 3.0.4 на целевой тысяче строк даст порядка 400 мс при пороге дебаунса 300 мс.

[WARNING]
Это *экстраполяция, а не замер*.
Opal-код может лечь на интерпретатор без JIT иначе, чем нативный JS, — как лучше, так и хуже.
Число получается только запуском 3.0.4 в QuickJS на устройстве, и до этого замера переход на 3.0.4 остаётся решением с неизвестной ценой.

== Как забрать результат асинхронного `convert`

Отдельный раздел, потому что наивный путь *молча даёт мусор*, а не падает.

`convert` в Asciidoctor.js 4 асинхронный.
Проверено на стенде:

[cols="2,2", options="header"]
|===
| Как вызвать | Что получится

| `evaluate<String>("Asciidoctor.convert(…)")` обычным скриптом
| `+Promise { <state>: "fulfilled" }+` — строка в 32 символа. Исключения нет
| модуль с `await` на верхнем уровне, значение последнего выражения
| `null`: модуль не является выражением
| модуль пишет результат в `globalThis`, забираем вторым вызовом
| корректный HTML
|===

Опасен именно первый вариант: стенд бодро отрапортовал бы «html: 32 символа», и это легко принять за пустой документ, а не за ошибку вызова.
Рабочий путь — третий, он и заложен в стенд.

Это единственное существенно новое знание из `T-013`: в документации quickjs-kt разворачивание промиса не описано.

== Что осталось непроверенным

. *Совпадение вывода 4.x с десктопным Ruby Asciidoctor* на нашем корпусе. Это шлюз, а не формальность.
. *Пик памяти QuickJS* на большом документе; есть ли API ограничения памяти — в документации не найден.
. *Поведение на бюджетном устройстве* — замеры сняты на флагмане.
. *iOS-ветка quickjs-kt*: собирается ли и работает ли на устройстве. Если да — отменяет запланированную реализацию через `JavaScriptCore` и меняет план работ.
. *Поведение `asciidoctor-kroki` 1.0.1 внутри движка*: тянет `pako` и `json5`, использует HTTP.
. Точное имя опции реестра расширений: документация расходится между `extension_registry` и `extensions_registry`.

== Что это меняет в плане работ

* `T-011` из «сравнить QuickJS и J2V8» превращается в «проверить, заводится ли бандл на quickjs-kt» — сравнивать с V8-вариантами больше нечего.
* `T-037` (корпус сравнения) поднимается вверх: он выбирает версию ядра, а не подтверждает результат.
* Если iOS-ветка quickjs-kt работает, `T-032` теряет смысл в текущей формулировке.

Изменения вносятся в план и видение отдельным решением, а не этим документом.
