== Документы

xref:asciidoc-editor-vision.adoc[Продуктовое видение]::
Проблема, скоуп, архитектура, принятые решения с обоснованием, риски и критерии успеха MVP.
Первое, что стоит прочитать; остальные документы опираются на него и не переопределяют.

xref:user-stories.adoc[Пользовательские истории]::
Сценарии по ролям и эпикам с критериями приёмки и разбивкой на этапы (MVP / IT2 / IT3).

xref:design/design.adoc[Описание дизайна]::
Визуальный язык, токены, компоненты и все экраны обоих вариантов раскладки со снимками.

xref:tasks.adoc[План работ]::
Задачи по потокам в порядке выполнения, с зависимостями, шлюзами и признаками готовности.
Здесь же список развилок, которые блокируют начало работы.

xref:documentation-rules.adoc[Правила ведения документации]::
Формат, структура, разметка и ссылки. Обязательны при создании и правке любого документа.

Решения (ADR)::

xref:adr/adr-002-android-first.adoc[ADR-002] — Android-first, iOS отложен.

xref:adr/adr-006-instrumented-tests.adoc[ADR-006] — тесты с живым движком и композицией идут инструментальным прогоном на устройстве.

Все ADR лежат в `adr/` сквозной нумерацией, включая решения уровня отдельной фичи (решение владельца, 2026-08-18): каталог один, номер выдаётся при заведении, фича указывается атрибутом `:feature:` в шапке.

xref:development-rules.adoc[Правила разработки]::
Спека раньше кода, тест раньше кода, цикл закрытия слайса, чеклист нефункциональных требований.
Обязательны; выведены из скиллов в `.claude/skills/` и адаптированы под стек проекта.

== Порядок чтения

. *Что за продукт* — «Проблема» и «Что делаем» видения.
. *Что именно делаем* — «Продуктовый скоуп» видения, затем истории нужного этапа.
. *Как это выглядит* — описание дизайна: сначала «Визуальный язык», потом экраны.
. *Как устроено внутри* — «Архитектура» и «Ключевые технические решения» видения.

== Прежде чем менять

* Формат — AsciiDoc, без исключений: см. xref:documentation-rules.adoc[правила].
* Решение живёт в одном документе; остальные ссылаются на него через `xref:`.
* Технические решения из видения переспорены не бывают по ходу дела — сначала меняется видение, потом всё остальное.
* Дизайн-бандл в `design/project/` — вход из внешнего инструмента, правки в нём затрёт следующий экспорт.
