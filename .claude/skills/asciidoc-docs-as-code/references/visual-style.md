# Фирменный вид

Дефолтная тема Asciidoctor узнаётся мгновенно и не в лучшем смысле. Всё ниже —
про то, как за час получить вид, который читатель не спутает ни с чем.

Философия: **AsciiDoc даёт роли (`[.role]`), CSS даёт вид.** Не лезь в HTML
руками и не пиши инлайн-стили в `.adoc` — иначе PDF-бэкенд и Antora развалятся.
Ставь роль в разметке, оформляй в CSS.

## Подключение

| Режим | Что делать |
| --- | --- |
| Antora | `signature.css` → `supplemental-ui/css/`, `enhance.js` → `supplemental-ui/js/`, подключить в `partials/head-styles.hbs` и `footer-scripts.hbs` |
| Asciidoctor | `docinfo.html` + `docinfo-footer.html` в каталог с `index.adoc`, атрибут `:docinfo: shared` |
| Confluence | тема не применяется — Confluence рендерит своим CSS; ставку делай на структуру, макросы и диаграммы |

Все переменные собраны в `:root` в начале `signature.css`. Смена палитры под
проект — это правка шести значений, не переписывание файла.

## 1. Хиро на лендинге

```asciidoc
[.hero]
--
[.hero-title]
Contact Center Platform

[.hero-sub]
Событийная платформа обработки обращений: Kafka, WebSocket, 4 канала, p99 < 200 мс.

[.badges]
image:images/badges/java.svg[Java 21]
image:images/badges/spring.svg[Spring Boot 3.5]
image:images/badges/license.svg[Apache-2.0]
--
```

Внутри hero стоят **абзацы с ролями**, а не заголовки: `= Заголовок` внутри
open-блока — невалидная конструкция, документ просто не соберётся. Крупный
кегль и градиент даёт CSS, а не уровень заголовка.

Бейджи в закрытом контуре тянуть с shields.io нельзя — сгенерируй SVG один
раз и положи в `images/badges/`.

## 2. Сетка карточек вместо оглавления

Список с ролью `cards` — CSS превращает его в сетку. Первая строка пункта
становится заголовком карточки, остальное — описанием:

```asciidoc
[.cards]
* xref:tutorial/quickstart.adoc[Быстрый старт]
  Поднять локальный стенд и обработать первое обращение за 15 минут.
* xref:how-to/kafka-retry.adoc[Ретраи и DLQ]
  Что делать с сообщениями, которые не обработались с третьей попытки.
* xref:reference/config.adoc[Справочник конфигурации]
  Все свойства `cc.*` с типами, дефолтами и влиянием на нагрузку.
* xref:explanation/architecture.adoc[Архитектура]
  Почему выбран event sourcing и чем за это пришлось заплатить.
```

Это единственный приём, который сильнее всего меняет впечатление от главной
страницы. Оглавление-столбик выглядит как черновик, сетка карточек — как
продукт.

## 3. Расширенные адмонишены

Пяти встроенных (`NOTE`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`) хватает
редко. Добавь роли поверх обычного блока:

```asciidoc
[.admonition.security]
****
Токен оператора живёт 15 минут и не должен попадать в логи. Проверка — в
`SecurityFilterTest#tokenIsMasked`.
****

[.admonition.perf]
****
Этот запрос делает full scan по `dialog_event`. На проде без индекса
`(dialog_id, created_at)` он даёт +2 с к p99.
****

[.admonition.gotcha]
****
`@KafkaListener` в этом классе не переживает ребалансировку: смотри
xref:how-to/kafka-retry.adoc#rebalance[раздел про ребалансировку].
****
```

CSS в `signature.css` рисует им цветной рельс, иконку и фон. Набор ролей:
`security`, `perf`, `gotcha`, `deprecated`, `experimental`.

## 4. Табы

Расширение `@asciidoctor/tabs` (Antora) или `asciidoctor-tabs` (CLI).
Синтаксис одинаковый, важен ровно шестизначный разделитель `======`:

````asciidoc
[tabs]
======
Java::
+
[,java]
----
var client = ChatClient.builder().baseUrl(url).build();
----

Kotlin::
+
[,kotlin]
----
val client = ChatClient.builder().baseUrl(url).build()
----

curl::
+
[,bash]
----
curl -sS "$URL/api/v1/dialogs" -H "Authorization: Bearer $TOKEN"
----
======
````

Правило: **порядок вкладок одинаковый на всех страницах**. Читатель
запоминает позицию, а не подпись.

Приятная деталь: без расширения блок деградирует в обычный список
определений с блоками кода — содержимое остаётся читаемым. Поэтому табы
безопасно использовать даже там, где часть конвейеров (например,
Confluence) расширение не подключает.

## 5. Код: callouts, подсветка строк, заголовки

```asciidoc
.ChatConsumer.java — обработка входящего события
[,java,highlight=3..5]
----
include::example$kafka/ChatConsumer.java[tag=consumer,indent=0]
----
```

Заголовок блока (строка с точкой) даёт подпись над кодом — мелочь, которая
резко улучшает сканируемость длинной страницы.

`highlight=3..5` работает с `highlight.js` и `rouge`; для Antora нужен
`source-highlighter: highlight.js` и версия Antora 3.1+.

## 6. Таблицы, которые не разъезжаются

```asciidoc
[cols="2,1,1,4", options="header", stripes=even]
|===
| Свойство | Тип | Дефолт | Что делает

| `cc.kafka.retry.max-attempts`
| int
| `3`
| Сколько раз повторить обработку до отправки в DLQ.
|===
```

Всегда задавай `cols` явно. Без этого ширины считаются по содержимому первой
строки и справочник конфигурации превращается в кашу.

Для длинных значений добавляй роль `[.compact]` — CSS уменьшит кегль моно и
поджмёт padding.

## 7. Микро-интеракции

`enhance.js` / `docinfo-footer.html` добавляет без единой зависимости:

- кнопку **Copy** на каждом `<pre>`;
- якорь-ссылку по ховеру на заголовках;
- полосу прогресса чтения сверху;
- переключатель светлой/тёмной темы с сохранением в `localStorage`;
- подсветку активного пункта оглавления при скролле.

Ничего из этого не требует сборки — файл кладётся как есть.

## Типографика

Значения по умолчанию в теме:

```css
--font-text: "Inter", "Segoe UI", "Helvetica Neue", system-ui, sans-serif;
--font-mono: "JetBrains Mono", "Cascadia Code", "SF Mono", Consolas, monospace;
--measure: 74ch;   /* ширина колонки текста */
--lh: 1.65;
```

Три вещи, которые дают 80% эффекта: ограничить ширину колонки (~70–80
символов), увеличить межстрочный до 1.6+, и не использовать один шрифт для
текста и кода.

Шрифты подключай системным стеком. Если нужен именно Inter/JetBrains Mono —
положи `.woff2` в репозиторий и подключи через `@font-face`; CDN за
периметром не работает и создаёт внешний egress, которого в доке быть не
должно.

## Тёмная тема

`signature.css` объявляет обе палитры и переключается по
`prefers-color-scheme`, а ручной тумблер ставит `data-theme="dark"` на
`<html>`. Единственное, о чём легко забыть: **SVG-диаграммы**. Экспортируй их
с прозрачным фоном и стилизуй через `currentColor` там, где возможно, иначе в
тёмной теме получишь белые прямоугольники. Подробнее — в `diagrams.md`.

## Чего не делать

- Инлайн `style=` в `.adoc` — сломает PDF и Confluence.
- `+++<div class="...">+++` passthrough-блоки ради вёрстки — не переживут
  смену бэкенда; используй роли.
- Больше трёх акцентных цветов — дока перестаёт читаться как единое целое.
- Анимации на скролле — в технической документации они мешают, а не украшают.
